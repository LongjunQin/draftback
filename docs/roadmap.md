# 回稿产品路线图(v3,2026-10-11)

> 2026-10-14 起产品改名为 Draftback / 回稿,原名 MDTurn;下文出现的旧名指同一产品。

> 给产品负责人看的计划书。v3 按第二轮外部审查修订:第一轮闭环补上"新版回到手机"这一程并用真实分发方式验收;安全收口与真实数据保护提到第一轮;编辑保存保真列为硬要求并在第一轮建立过渡保护;状态改为三个独立维度;Mac 换壳的对照数据必须在同一台 Mac 上取得;第三轮末设"自用版完成"节点。
> 批注后由智能体修订。

## 1. 已定的决定

| 事项 | 决定 |
|---|---|
| 首批用户 | 只有本人。先自己用到满意,再决定公开上架。期间用 TestFlight 内部测试装到自己的 iPhone,不受商店地区限制;每个构建有效期 90 天,到期重传 |
| 自用版完成节点 | 第三轮结束。公开产品化与正式上架是下一阶段的独立决策,不影响先完成一个可靠的个人版本 |
| 正式上架地区 | 上架前再定。若要国内区,需 App 备案;App 备案与网站备案是不同程序,是否因此需要自建国内服务,届时按实际架构核实,不预先断定 |
| 开发者主体 | Apple 个人开发者账户(每年 99 美元,商店显示法定姓名) |
| 技术路线 | 优先复用现有 Web 渲染与批注能力;iOS 用原生外壳承载 Web 内核;**Mac 是否换成原生外壳不预先决定,既可能继续后置,也可能在第一轮提前触发**,规则见第 6.1 节 |
| 同步 | 首版用 CloudKit 做 Apple 设备间同步;Windows 接入方式(CloudKit JS 或其他)另行验证后再定 |
| 服务器 | 不自建,直到出现第 8 节的触发条件 |
| 编辑保存保真 | 硬性要求。只改一个字不得导致全文重排,见第 6.2 节 |
| 不做 | 纯原生重写、账号注册体系、团队协作、协同编辑、打包 pandoc |

## 2. 三条原则(第一性原理)

1. **可靠性是底线,功能数量是其次。** 产品的根本价值是"人的判断准确、可靠地到达智能体"。一条批注丢了、一次改错了版本、一次保存把原稿悄悄改了,比少十个功能更致命。
2. **最大的未知最先、最便宜地验证。** 真正没把握的只有三件:iPhone 上划词批注的体验,Electron 版 Mac 接 CloudKit 的可行性,所见即所得编辑能否做到局部回写。其余都是已知工作量。
3. **先为唯一用户做,够用即可。** 首批用户是本人,凡是"公开上架才需要"的事(双语、官网、隐私页、更新机制)都往后放,但保护本人真实资料的事不往后放。

## 3. 现状(2026-10-11 核实)

| 项目 | 现状 |
|---|---|
| 技术栈 | Electron 43 外壳 + 本地 Node 服务 + Web 渲染;Milkdown 所见即所得编辑 |
| 安装包 | macOS DMG 126MB,未公证;Windows EXE 未签名 |
| 已有功能 | 打开、多标签、大纲、划词批注、审阅状态机(含冲突、取消、完成、定稿语义)、所见即所得编辑、保存(仅编辑模式)、缩放、公式、Mermaid、代码高亮、智能体 CLI 协议、正文渲染缓存 |
| 没有的功能 | 新建、另存为、导出(PDF/Word/HTML)、打印、查找替换、深色模式、拖放打开、文件夹浏览、设置页、自动更新 |
| 产品层问题 | 任何文件一打开就创建审阅会话并加锁,没有"普通阅读"和"普通编辑"状态 |
| 编辑保真问题 | 所见即所得模式只改一个字也会整篇重新序列化,格式被规范化,原始 HTML、Front Matter、脚注等有被改写风险;编辑器没有现成的原文范围映射(底层解析结果带位置信息,但转入编辑器时丢失) |
| 安全问题 | 渲染开着原始 HTML,Mermaid 为宽松模式,主页面无内容安全策略。风险在文档内容而不在来源:智能体抓网页写成的文档也可能夹带代码;页面与本地服务同源,夹带的代码可以读到其他打开中的文档并外发。受威胁的是本人的真实资料 |
| 恢复问题 | `mdreview wait` 有默认超时,本地服务随 App 退出,没有恢复流程 |
| 上架层问题 | 界面只有中文;未公证;无官网与隐私政策页 |

## 4. 假设与验证方式

以下都是**假设**,不是结论。每一条写明怎么验证、在哪一轮验证。

| 假设 | 验证方式 | 轮次 |
|---|---|---|
| 现有渲染与批注代码在 iPhone 的 WKWebView 里可用,中文长按选字、跨段选择、表格与图片批注可接受 | 真机、真实图文方案,逐项测 | 第一轮 |
| Electron 版 Mac 能接上 CloudKit(原生辅助进程或 CloudKit JS 二选一),且真实安装后可稳定使用 | 真实签名的 Mac 安装包 + TestFlight 的 iPhone 客户端,连同一容器的生产环境,跑完整闭环;不只证明接口能调用 | 第一轮 |
| 同一条批注在 Chromium 与 WebKit 中定位一致 | 同一文档两端对照 | 第一轮 |
| 现有性能问题的来源 | 测冷启动、大文档、Mermaid、划词、批注保存、编辑输入、多标签切换,拿数据再说 | 第一轮 |
| 原生外壳能明显降低 Mac 包体积与内存 | 只在 Electron 接 CloudKit 结果不佳时做 Mac 原生最小壳对照样例,**同一台 Mac、同一文档、相近功能**对比体积、内存、启动;iPhone 样例的数据不能用来证明 Mac 换壳的收益 | 第一轮(按需) |
| 所见即所得编辑可以做到块级局部回写 | 第 6.2 节的三个小样;小样通过后再确认工程量 | 第一轮出小样结论 |
| CloudKit 推送在前台在线场景下延迟可接受 | 实测并定目标值;离线、休眠、服务退出时显示等待状态并靠重拉保证最终到达 | 第二轮 |
| Word 导出用 JS 库自写映射可达"真实文档可用" | 用真实方案验收表格分页、中文字体、图片尺寸、公式清晰度、标题层级、链接 | 第四轮 |

## 5. 跨端规则(首版,第一轮产出正式文档)

### 5.1 两种流程分开

- **Mac 发起的审阅**:Mac 管原文、版本和审阅轮次。手机只针对指定版本提交批注,不改原文。
- **手机独立打开的文件**:单独管理,与 Mac 发来的会话无关,即使文件名相同。

### 5.2 身份识别

- 用稳定的文档标识、会话标识、版本指纹识别跨端文档;不靠文件名,不靠 Mac 绝对路径。
- 明确文件改名、移动、复制、另存为之后的身份规则。

### 5.3 同步不整份覆盖

- 批注先在本机可靠保存,强退后仍在。
- 一批批注完整接收且版本校验通过后,才进入"待改稿";批注未完整接收时不得提前改稿。
- 重复上传不重复执行;迟到的旧数据不覆盖新的处理状态。
- 冲突批注保留,不静默丢弃;有接收回执、重试、去重和恢复入口。
- 手机批注的版本与 Mac 当前原文不一致时,明确提示,不改错稿。

### 5.4 快照内容

会话快照包含 Markdown 正文、必要的图片与附件、资源清单与版本、相对路径解析规则;资源缺失时提示。外链图片是否缓存、断网能否完整阅读、指向其他 Markdown 的链接如何处理,第一轮定。

### 5.5 状态分三个独立维度

不用一组界面状态替换现有审阅状态机。三个维度各自定义、各自显示:

1. **界面模式**:阅读、编辑。
2. **审阅生命周期与当前写入者**:沿用现有状态机的冲突、取消、完成、定稿等语义,只增加"普通编辑中"的登记,防止智能体在用户编辑时冻结或覆盖。
3. **同步状态**:待上传、上传中、已接收、失败、等待回执。

保留现有写入状态检查、版本校验、幂等、备份、原子写入、外部变化检测。冻结审阅期间不能直接覆盖被批注版本,只能另存副本。

### 5.6 状态权威

共享同一套状态转换规则;每种操作明确由谁提交、谁校验、谁最终落盘;桌面 UI、CLI、同步模块遵守同一套事务规则。现有命令与旧数据向后兼容,新能力通过明确版本与字段扩展。

### 5.7 手机侧状态链

手机已保存 → 等待同步 → Mac 已接收 → 等待智能体 → 修改中 → 新版可复核。不把"已上传"显示成"正在改稿"。

### 5.8 真实数据保护(首次处理真实文件前完成)

- 旧会话与批注可备份、可恢复:动真实文件前先整体备份数据目录。
- 上传范围明确:只上传明确"推到手机"的会话,不上传其他文档。
- 账号变化时不把旧队列上传到新账号:待上传项记录所属账号。
- 文档资源访问范围有边界;原生桥只开放最小权限。
- 安全收口:默认不执行文档里的原始 HTML(按文本显示,可对单个文档明确开启)、Mermaid 改严格模式、主页面加内容安全策略、远程图片与链接加载策略。

## 6. 四轮计划

周期为粗估,每轮按验收标准收口,不按日历。两条线并行:**主线**是真实签名安装包下的最小真机审阅闭环,占用主要精力;**阅读器线**是低风险、可独立交付的小功能,每项独立验收,不与状态机重构捆绑交付,不作为主线的前置条件。

### 第一轮:分离阅读与审阅,跑通真机闭环,建立数据与保存保护(约 3 到 5 周)

主线:

1. 状态按第 5.5 节分三维度落地;"开始审阅"成为明确动作。
2. 跨端规则(第 5 节)写成正式文档。
3. 真实数据保护(第 5.8 节)全部完成,再碰真实文件。
4. 最小真机闭环,用计划中的真实分发方式:Developer ID 签名的 Mac 安装包 + TestFlight 内部测试的 iPhone 客户端,连同一个 CloudKit 容器的生产环境;数据结构部署与实际数据同步分别验证。至少真实完成一次:**Mac 发稿 → 手机阅读与划词批注 → 提交 → 智能体修改 → 手机收到新版**。处理说明的精细展示、改动定位、多轮体验可后续完善,主链路本轮跑通。
5. Electron 接 CloudKit 试一种接法,按第 6.1 节规则决定 Mac 外壳走向。
6. 性能测量,拿到数据。
7. 编辑保存过渡保护与三个小样(第 6.2 节)。

阅读器线(并行填充):深色模式、查找、拖放打开、基础 PDF 导出与打印。PDF 先覆盖真实方案的基本需要,复杂分页与排版另行安排。

验收:

- 在 iPhone 上完整读到一份带图片和表格的真实方案,准确划词批注,提交后 Mac 上的智能体改稿,新版回到手机,整条链路用真实分发包跑通一次。
- 第 5.8 节各项可演示:备份可恢复,未推送的文档不上传,原始 HTML 默认不执行。
- 三个编辑小样有明确结论;过渡保护生效,所见即所得保存不再静默改写原稿。
- 拿到性能数据;若做了 Mac 对照样例,拿到同机对比数据。

需要你亲自办:申请 Apple 个人开发者账户(本轮唯一的外部依赖;Developer ID 签名、iCloud 权限、TestFlight 都靠它)。

#### 6.1 Mac 外壳决策规则

Electron 接 CloudKit 的真实集成成本决定走向。原生桥接要处理辅助进程、签名、权限和分发;CloudKit JS 要验证网页认证及后续使用体验。不能只证明接口能调用,要证明真实安装后可稳定使用。

- 接入稳定、体验可接受、维护成本合理:继续保留 Electron。
- 接入或分发明显复杂,原生壳有望显著简化:立即增加一个 macOS 原生最小壳对照样例(原生外壳装载同一套 Web 内核),同机对比后允许提前迁移。
- 两种方案都有问题:先定位问题来源;不能默认换壳就会解决同步与恢复问题。

#### 6.2 编辑保存保真

目标:保留原始 Markdown 源码;跟踪用户实际修改的块;只重新生成并替换实际受影响的语法范围;未受影响的原文区域保持字节一致;源码视图作为特殊语法和异常情况的兜底。"块级"不机械等同于单个段落:段落拆分、合并、嵌套列表、引用块等操作按原文块序列对齐后,把连续受影响的范围一起替换,但不能因此退回全文重写。

第一轮做两件事:

- **过渡保护**:保存前对比原文与待写入内容,显示将改动的处数,并标出超出本次编辑范围的部分;由用户选择保存、另存副本或取消。未验证可安全回写的内容,暂用源码编辑或保留原文块。在此之前不得静默改写原稿。
- **三个小样**:① 普通段落改一个字,文档同时含 Front Matter、原始 HTML、公式和特殊空白,未修改区域字节一致;② 嵌套列表内改文字,正确保留未受影响的编号、缩进、空行和续行;③ 段落拆分、合并、跨块操作及撤销,存在相同文本段落时也不能回写到错误位置。

小样通过后,块级回写在阅读器线上实现,第三轮末自用版完成前交付;"工程量中等"是初始估计,小样后确认。实现难度的不确定性不能成为降低保真标准的理由。

### 第二轮:可靠的跨设备审阅闭环

主线:本地持久保存、版本校验、重试与去重、接收回执、离线与强退恢复、`mdreview wait` 超时与 Mac App 退出重开后的接续、新版回传中断后的恢复、批注未完整接收时不提前改稿、手机侧状态链、推送延迟实测与等待状态。

阅读器线:块级回写实现(小样通过后);其余小件按需。

验收:断网、强退、重复提交、旧版本返回、回传中断五种情况下,不丢意见、不改错稿;Mac App 退出重开后智能体等待可接续。

### 第三轮:逐步抽共享内核,iOS 完整审阅与复核,自用版完成

主线:按前两轮结果确定内核边界,渐进抽取,不一次搬完;CLI 与 sidecar 向后兼容;iOS 端收到新版后能看每条意见的处理结果与说明、定位到相关内容、继续下一轮或定稿;iOS 文件访问方式定稿(导入副本还是原位编辑、目录授权、sidecar 存放、重启后恢复、权限失效处理)。

阅读器线:块级回写交付;新建、另存为、随时保存。

验收:Mac 原有流程全部正常,现有自动化测试全绿并新增跨设备测试;iOS 完整走完审阅、改稿回传、复核;所见即所得保存通过三个小样对应的回归测试。

**自用版完成节点**:以上验收全部通过,本人日常用 Mac 与 iPhone 完成审阅闭环不需要绕路,即为自用版完成。是否公开产品化,此时另行决策。

### 第四轮:公开产品化(下一阶段决策后启动)

1. 编辑器扩展:文件夹目录树、"最近文件"、粘贴图片、字数统计、设置页。
2. 导出 Word 与单文件 HTML,按第 4 节验收;明确"公式转图片即失去公式可编辑性"的取舍。
3. 上架前必做清单(第 7 节)。
4. Mac 换壳若第一轮未触发,在此单独评估收益与成本。

验收:不接触智能体的人也认为这是一款完整的 Markdown 工具;通过 App Store 审核。

## 7. 上架前必做清单

公开上架前完成,自用阶段不阻塞:

- 界面与菜单双语。
- 域名、静态官网、隐私政策页;隐私政策在 App 内也能找到。
- 自动更新;旧 sidecar 与会话迁移;Mac 与 iOS 版本不一致提示;最低系统版本与支持设备范围;升级失败恢复。
- 云端数据生命周期:哪些文档上传、是否用户主动开启、保留多久、如何删除、切换账号时本地缓存处理、通知是否显示敏感标题。
- 决定上架地区(见第 1 节)。
- 若进入 Mac App Store,另评估沙盒、CLI 集成、本地服务与文件访问;Electron 本身可上架,不必为此换壳。

## 8. 自建服务器的触发条件

满足任一条才做:Windows 用户明确需要跨设备同步且 CloudKit JS 方案验证不可行;需要网页链接分享给没装 App 的人;需要团队账号;正式上架国内区经核实确需国内接入服务。做时一台轻量服务器即可,区域与规格按当时用户所在地、用户量、文件体积与访问量估算,不预设。

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| iPhone 划词批注体验不达标 | 第一轮就暴露;可退到"手机只读与整段批注",再评估原生选区方案 |
| Electron 接 CloudKit 两种接法都别扭 | 按第 6.1 节规则处理,必要时做 Mac 原生最小壳对照样例 |
| 同步丢批注或改错版本 | 第二轮五种故障场景作为验收红线 |
| 抽内核打坏现有协议 | 现有自动化测试全部保留并新增跨设备测试 |
| 块级回写做不到无损 | 不能无损的语法保留源码块;源码视图兜底;保真标准不降 |
| TestFlight 构建 90 天过期 | 自用期间按期重传,记入日程 |
| 周期估算偏乐观 | 每轮按验收收口;阅读器线随时可停 |
