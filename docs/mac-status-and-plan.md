## 0. 先说结论

| 你的问题 | 回答 |
|---|---|
| 电脑版功能做到哪了 | **闭环的主干已经通了,常用的阅读器功能也补齐了。** 普通阅读、普通编辑、审阅三种状态分开;划词批注精确到字;原文冻结;智能体按批注改稿后自动刷新;编辑保存只改你动过的块;推到手机、收批注、回执、改稿摘要都能用。**缺的是闭环的"后半段"**:交出去后怎么知道有没有 AI 接手、稿子回来怎么确认改对了(尤其是被删掉的内容)、改错了怎么退回。这三件要先定规则再做界面。常规小功能另有十来件,逐项补。 |
| 架构要不要改 | **不用推倒。** 四块分工(Electron 外壳、本地服务、网页界面、同步辅助程序)是对的,继续用 Electron。要做的是两处随功能渐进的整理(界面代码拆模块、菜单与动作合一)和一个要单独设计的功能(轮次版本记录)。 |
| 顺序怎么排 | **电脑端全部做完 → 手机端 → 跨端规则修订与可靠性验收 → 分发。** 一次只做一端,避免来回改。唯一的例外在"合同层":审阅状态、轮次、版本记录、接手这几条规则,是两端共用的合同,在电脑端定的时候就按两端通用来定,每条多写一句"手机上显示成什么",但不做手机界面。返工来自合同变了,不来自界面晚做。 |

**下一版最有价值的验收**:让一个没参与开发的人独立完成一轮——交出批注、知道有没有人接手、发现一处被删掉的内容、判断是否接受修改、并能退回去。

## 1. 电脑版现在能做什么

按你用的时候的视角列,每一项都有自动化测试或装机验证。

| 场景 | 现在能做的 |
|---|---|
| 打开与阅读 | 双击 .md、⌘O、从访达拖进窗口、智能体 `mdreview open` 直接送到面前;多标签;左栏大纲;正文缩放;深色模式跟随系统;⌘F 查找(计数、上下个、高亮);公式、Mermaid 图、代码高亮、表格、任务列表;最近文件(左栏与欢迎页);GBK / UTF-16 编码的文件按原样显示、只读不写坏 |
| 普通编辑 | 所见即所得编辑;⌘S 保存只改你动过的块,其余字节不变(含 Front Matter、原始 HTML、公式、列表缩进);覆盖前自动备份(每篇留 10 份);文件在外面被改会重新载入;编辑期间智能体不能冻结这篇(编辑登记) |
| 审阅闭环(前半段) | 「开始审阅」冻结原文并记指纹;划词批注,标题、表格、代码块、跨段落都能选;「完成本轮审阅」;智能体 `begin-apply` → 改文件 → 逐条标「已处理 / 不处理」→ `complete --summary`;回稿自动刷新;冲突、取消、定稿、人工解锁后自己改,语义齐全;每条批注的去向有记录 |
| 手机联动 | 开审阅时自动推到手机(正文、图片附件、状态);手机批注交回后 Mac 自动收下并回执;改稿中手机看到横幅;改完手机正文自动换新并带摘要;`mdreview sync-status` 看每篇状态 |
| 导出 | PDF(⇧⌘E)、打印(⌘P)、单文件 HTML、Word(需电脑装有 pandoc) |
| 新建 | ⌘N 或欢迎页新建,选位置后直接进编辑 |
| 安全与数据 | 文档里夹带的原始 HTML 不执行、Mermaid 严格模式、内容安全策略;本地服务只听本机并校验来源;整体快照备份与恢复(`mdreview snapshot / restore`);审阅索引启动自清理;保存中断自动恢复 |
| 给智能体的命令 | `mdreview` 共 12 条:open、status、wait、begin-apply、complete、push、sync-status、unlock、snapshot、snapshots、restore、import-batch |

**闭环的后半段现在是什么样(核实过的事实)**:

- 点「完成本轮审阅」只是把状态改成"等待改稿"。`mdreview wait` 是智能体那边每 2 秒轮询状态,**服务端不知道有没有人在等**;而且 wait 一看到你交出批注就退出、把活交给智能体去读。今天能闭环,全靠智能体一直在后台挂着 wait。你自己开一篇、批完、交出去,没有智能体在等的话稿子会一直挂着,界面却显示"已交给 AI"。
- 稿子回来只换正文加一条系统通知,**改之前的原文没有留底**,所以看不到改了什么、也退不回去。
- 每条批注的处理说明有(旁注文件里),但那是 AI 的自述,不是正文差异。
- 手机交回的批次,Mac 按文档标识找最新一轮,再核对状态和正文指纹;批次里带着的会话编号**没有拿来核对**。平时没事,一旦有了"恢复到旧稿",正文和旧轮一字不差,旧批次就会被当成新一轮收下。

**还没有的常规功能**(UI 方案 1.2 节「要补」):设置窗口、菜单栏里的「打开最近文件」子菜单、「在访达中显示」、「另存为副本」、粘贴为纯文本、快速打开、编辑模式的查找替换、字数统计、图片粘贴落盘到文档旁、任务列表阅读时的只读勾选框、⌘K 插入链接。

## 3. 架构要不要改

**不动的**:四块分工;继续用 Electron;本地服务 + 文档旁注文件的协议;所见即所得编辑 + 块级回写;`mdreview` 命令与旁注文件格式(智能体和旧数据都靠它;新增命令只加不改)。

**两处整理,随功能渐进做,不单独排期**:

| 整理 | 做什么 | 规矩 |
|---|---|---|
| 界面代码拆模块 | desktop.js 按「标签与文档 / 阅读与批注 / 编辑 / 查找与导出 / 状态与同步」逐步拆开 | 从现在起新功能一律新开模块,不再往 desktop.js 里加;改到哪块就顺手把那块拆出来 |
| 菜单与动作合一 | 「动作名、快捷键、在菜单哪、在工具栏哪、什么状态下可用」做成一张表,菜单栏和工具栏按表生成 | 随最小界面骨架一起落,先只覆盖闭环动作,其余菜单项逐步迁入 |

**一个要单独设计的功能:轮次版本记录**。它同时承担对比、历史、恢复三件事,还牵动收批次的校验规则(第 4.1 节规则⑤);设计定了再估工期,不套"一两天"。

**知道但不急的技术债**:快照整份复制(每份约 1.3 MB);导出 Word 依赖 pandoc(公开版前定随包还是换纯 JS);Windows 包自 0.4.1 后没重打;编辑模式没有查找替换。

## 4. 电脑端怎么做完

电脑端"做完"的定义:五条规则定稿 → 闭环后半段做出来 → 常规功能补齐 → 页面布局(骨架与皮肤)落地 → 装机验收通过。分三步:

| 顺序 | 交付重点 | 验收 |
|---|---|---|
| **先做** | 五条规则(4.1 节)、最小界面骨架(4.2 节)、AI 接手路径 | 没参与开发的人独立交出一轮批注,并一眼知道有没有人在听、有没有人领取 |
| **第一批** | 回稿卡、含删除的完整改动对比、轮次留底与恢复;跑通多轮复核 | 三轮加恢复的场景(规则⑤);发现一处被删内容;判断接受与否;能退回 |
| **第二批** | 常规功能按使用频率逐项(第 1 节末尾那十来件,「图片粘贴落盘」先验证是不是真丢);左栏「稿件 / 大纲」、菜单栏按 UI 方案 1.3 节重排、动作表补全;统一视觉(颜色、字体、间距、图标) | 对照 UI 方案第 3 节逐屏核对;不接触智能体的人也觉得是完整的 Markdown 工具 |

阅读、编辑、保存的基本体验贯穿始终继续做好,不等任何一批。每批出一个版本装到你电脑上。手机端在这期间不动(服务端为规则①②⑤做的改动天然两端通用,不是"顺手做手机")。

### 4.1 五条规则(请逐条拍板;每条末尾一句是手机上的显示,现在只定不做)

**① 状态:稿子在谁手里,只有这几种**

| 状态 | 谁手里 | 电脑界面怎么说 |
|---|---|---|
| 批注中 | 你 | 「批注中 · N 条」 |
| 已交出,没人在听 | 没人 | 「已交出 · 还没有 AI 接入」+「复制改稿指令」按钮 |
| 已交出,有程序在听,还没领取 | 等 AI 领 | 「已交出 · AI 在线,等待领取」 |
| AI 已领取 / 正在改 | AI | 「AI 正在修改…」(锁定,不能批注) |
| 稿子回来了 | 你 | 回稿卡 + 「显示改动」默认开 + 主按钮变「通过 · 定稿」/ 再批注 |
| 定稿 | 结束 | 「已定稿」 |
| 冲突 | 需要你处理 | 「文件在外面被改了 · 处理…」 |

手机:同一套状态,文案同上,放在首页每行和文档页顶栏。

**② 交接:AI 怎么接手**

- "有程序在听"和"AI 已领取"是两件事,分开记:
  - **监听登记**:`mdreview wait` 启动时向服务端登记(智能体名字、时间),**每 30 秒续期,90 秒没续期就失效**;程序强退不会留下假在线。登记只表示"有程序在监听",不表示接手。
  - **领取**:以真实事件为准——`mdreview begin-apply` 成功,或新增的 `mdreview claim` 明确领取本轮。界面只在领取后才显示"AI 正在修改"。
- 没人在听时,「复制改稿指令」把一段现成的话复制到剪贴板(文件路径 + 要执行的 mdreview 命令),贴给任何智能体都能接上。
- 有程序在听但超过一定时间(比如 10 分钟)没领取,状态区提示「AI 在线但还没开始,可以重新复制指令」。
- 首次使用场景(自己开一篇、批注、交出、让 AI 接手)列入核心验收。

手机:显示同样三档(没人在听 / 在线等待领取 / 正在修改);「复制改稿指令」手机上不做。

**③ 开轮:什么时候算开始新一轮**

- 普通打开的文档,**首次成功保存一条文字批注或总体意见时**自动开第 1 轮并锁定原文(提示一次"原文已锁定")。
- 稿子回来后同样:首次成功保存批注时开下一轮。只选字、只打开输入框又取消,都不改轮次,回稿卡不消失。

手机:同一规则;手机上开下一轮需要服务端支持,电脑端做规则时一并留好接口,手机界面以后做。

**④ 定稿**

- 一条批注都没有时主按钮是「通过 · 定稿」,确认一次(它告诉 AI 这篇结束了)。
- 稿子回来后主按钮同样是「通过 · 定稿」;有新批注则变回「交给 AI」。

手机:同一规则;手机定稿同样只留接口,界面以后做。

**⑤ 恢复与版本记录**

- 每一轮都留底:交出时的原稿、回来时的完成稿、这一轮的批注与逐条处理结果,四者对应到同一个轮次号;人工改稿(「我自己改」)同样留底。
- 「显示改动」对比的是本轮原稿与完成稿:**新增、删除、替换三种都显示**,段落移动先显示为删旧加新。回稿卡上的处理说明是 AI 的自述,正文差异才是复核依据,两者都有。
- 「恢复到第 N 轮改稿前」:**不删当前稿**,把当前稿记成一个新版本,再把正文换回第 N 轮原稿;历史各轮的批注与处理结果原样保留。
- **恢复产生新的版本身份**(新的会话编号与轮次)。收手机批次时**同时校验轮次身份(会话编号)和正文指纹**:旧轮的批次即使正文一字不差也拒收,回执写「轮次已推进」。
- 验收场景:完成三轮,恢复到第二轮改稿前,再改一轮;此时手机交回第二轮的旧批注,正文完全相同、轮次不同,Mac 必须拒收并明确提示,不改错稿。

手机:显示每轮的结果需要新的记录格式,格式在电脑端这一步定好;手机界面以后做。

### 4.2 最小界面骨架(先做阶段落地的部分)

工具栏:状态区(居中)、主按钮(右)、阅读 / 编辑切换、批注栏开关、查找、导出——六样,位置按 UI 方案第 3 节,样式用默认值。左栏先不改。颜色、图标、版心用现有的,第二批再统一调。

## 5. 总流程(电脑、手机、跨端、分发怎么排)

| 阶段 | 做什么 | 说明 |
|---|---|---|
| A 定义 | 拍板第 4.1 节五条规则(按两端通用来定,只多写"手机显示什么"一句);UI 方案 13 问里只定与闭环动作相关的几问(主按钮名字、开轮时机、交出不弹确认、删除可撤销、每轮留底) | 颜色、图标、版心、主题用推荐默认值,不前置;13 问里的手机问题暂缓 |
| B 电脑端 | 第 4 节三步,直到"电脑端做完"的定义全部满足 | 期间不动手机 |
| C 手机端 | 按 A 阶段定好的规则做手机界面:底栏「批注这段 / 交给 AI」、回稿卡、逐条结果、手机定稿、稿子回来直接开下一轮 | 到时主要是界面工作,状态和记录格式已在 B 阶段定好 |
| D 跨端 | 《跨端规则》按 A 阶段的规则做小修订(状态名、版本身份、批次校验);可靠性验收:断网、强退、重复提交、旧版本返回、回传中断、云端环境重置 | 通道已通,这一步是修订加验收,不是新课题 |
| E 分发 | 商标域名(你办)、CloudKit 生产环境、Developer ID 签名公证、TestFlight、商店 | 你已定等定版后 |
